## ADDED Requirements

### Requirement: 直播间租户隔离维护

系统 SHALL 在租户上下文中提供直播间的创建、查询、更新与删除能力。所有直播间查询 MUST 在数据库查询阶段注入租户过滤；写操作 MUST 通过`tenant_id`与记录`ID`双条件定位，跨租户访问 MUST 表现为记录不存在。直播间 MUST 拥有同租户内唯一的`room_code`业务编码。

#### Scenario: 创建直播间

- **WHEN** 具备`live:room:add`权限的用户提交直播间编码、名称、类型与状态
- **THEN** 系统在当前租户下创建直播间记录，创建人与租户归属取自当前上下文
- **AND** 响应返回新直播间`ID`

#### Scenario: 直播间编码同租户唯一

- **WHEN** 同一租户下已存在相同`room_code`的直播间，再次创建相同编码
- **THEN** 创建失败并返回唯一约束业务错误
- **AND** 其他租户不受影响

#### Scenario: 列表按租户隔离并支持筛选分页

- **WHEN** 具备`live:room:query`权限的用户按名称模糊、类型或状态查询直播间列表
- **THEN** 系统在数据库侧完成租户过滤、筛选、排序与分页后返回当前页数据
- **AND** 结果不包含其他租户的直播间

#### Scenario: 删除仍被直播内容引用的直播间被拒绝

- **WHEN** 用户删除一个仍存在未删除直播内容引用的直播间
- **THEN** 系统返回`LIVE_MANAGE_ROOM_REFERENCED`业务错误且不删除该直播间
- **AND** 无引用的直播间可被软删除

#### Scenario: 跨租户详情访问表现为不存在

- **WHEN** 用户以其他租户直播间的`ID`请求详情、更新或删除
- **THEN** 系统返回记录不存在业务错误，不泄露该记录存在性

### Requirement: 直播间下拉候选

系统 SHALL 提供直播间有界下拉候选接口，返回当前租户内直播间的最小投影（`ID`、编码、名称、状态），支持关键字筛选，单次返回数量 MUST 有固定上限并在文档中说明超限行为。

#### Scenario: 直播内容表单加载直播间候选

- **WHEN** 具备`live:room:query`权限的用户以关键字请求直播间候选
- **THEN** 系统返回当前租户内匹配的最小投影列表
- **AND** 返回数量不超过固定上限，不返回描述等大字段

### Requirement: 直播内容租户隔离维护

系统 SHALL 在租户上下文中提供直播内容的创建、查询、更新与删除能力，覆盖主题、正文、页面/推流/播放/封面地址、歌单、领唱、伴奏、主持人、讲道主题、讲员、讲员身份、经文引用与内容、大纲、设备说明、接待安排、状态、公开性、直播日期与开播时间。直播内容 MUST 关联同租户内存在且未禁用的直播间。

#### Scenario: 创建直播内容并校验直播间

- **WHEN** 具备`live:live:add`权限的用户提交关联有效直播间的直播内容
- **THEN** 系统在当前租户下创建直播内容并返回新记录`ID`
- **AND** 关联直播间在同租户内不存在或状态为禁用时，创建失败并返回对应业务错误

#### Scenario: 歌单以 JSON 数组维护

- **WHEN** 用户提交非空歌单
- **THEN** 系统校验其为合法`JSON`数组后存储
- **AND** 非法`JSON`创建失败并返回参数错误

#### Scenario: 列表批量装配直播间名称

- **WHEN** 具备`live:live:query`权限的用户查询直播内容列表
- **THEN** 系统在数据库侧完成租户过滤、筛选、排序与分页
- **AND** 使用一次批量查询装配当前页记录的直播间名称，不产生随行数线性增长的逐行查询

#### Scenario: 更新与批量删除受租户与权限约束

- **WHEN** 具备`live:live:edit`或`live:live:remove`权限的用户更新或批量删除直播内容
- **THEN** 系统仅命中当前租户内的记录，跨租户`ID`表现为不存在
- **AND** 删除为软删除，重新启用或查询历史数据时不丢失

### Requirement: 直播开启与关闭状态动作

系统 SHALL 提供直播开启与关闭状态动作接口（`PUT /live/{id}/start`、`PUT /live/{id}/stop`），分别受`live:live:start`与`live:live:stop`权限点保护。开启 MUST 校验目标直播处于`未开始`状态、关联直播间存在且未禁用、同房间不存在其他`进行中`直播，成功后记录开播时间并将直播间置为`直播中`。关闭 MUST 校验目标直播处于`进行中`状态，成功后将直播置为`已结束`并将在播直播间恢复`空闲`。状态迁移与直播间状态联动 MUST 在同一事务内完成，且所有读写 MUST 注入租户过滤。

#### Scenario: 开启直播成功

- **WHEN** 具备`live:live:start`权限的用户对`未开始`的直播执行开启
- **THEN** 系统在同一事务内将直播置为`进行中`、记录开播时间，并将关联直播间置为`直播中`
- **AND** 操作人与租户归属取自当前上下文

#### Scenario: 开启被状态机拒绝

- **WHEN** 用户对`进行中`或`已结束`的直播执行开启
- **THEN** 系统返回状态迁移业务错误且不修改任何数据

#### Scenario: 直播间被占用时开启被拒绝

- **WHEN** 同一直播间内已存在另一场`进行中`的直播，用户开启同房间的新直播
- **THEN** 系统返回直播间占用业务错误且不修改任何数据

#### Scenario: 直播间禁用时开启被拒绝

- **WHEN** 关联直播间处于`禁用`状态时用户执行开启
- **THEN** 系统返回直播间不可用业务错误且不修改任何数据

#### Scenario: 关闭直播恢复直播间

- **WHEN** 具备`live:live:stop`权限的用户对`进行中`的直播执行关闭
- **THEN** 系统在同一事务内将直播置为`已结束`，并将处于`直播中`的关联直播间恢复`空闲`
- **AND** 已开播时间保持不变

#### Scenario: 状态动作按租户与权限约束

- **WHEN** 用户以其他租户的直播`ID`执行开启或关闭
- **THEN** 系统返回记录不存在业务错误，不泄露记录存在性
- **AND** 未具备对应权限点的请求被统一权限中间件拒绝

### Requirement: 直播枚举字典治理

系统 SHALL 通过字典模块维护直播管理枚举标签：`plugin_live_room_type`（`1`=正常聚会，`2`=活动，`3`=其他）、`plugin_live_room_status`（`0`=空闲，`1`=直播中，`2`=禁用）、`plugin_live_state`（`0`=未开始，`1`=进行中，`2`=已结束）、`plugin_live_public`（`1`=公开，`0`=私有）。后端代码 MUST 使用命名常量表达枚举值，前端 MUST 通过字典数据渲染标签。

#### Scenario: 插件安装写入直播字典 seed

- **WHEN** 插件安装`SQL`执行
- **THEN** 四个直播字典类型及其枚举数据被幂等写入宿主字典表
- **AND** 重复执行安装`SQL`不产生重复字典数据

#### Scenario: 前端枚举列渲染字典标签

- **WHEN** 用户打开直播间管理或直播内容管理页面
- **THEN** 类型、状态、公开性列展示字典标签而非原始数值

### Requirement: 直播管理菜单与权限点

系统 SHALL 声明直播间管理与直播内容两个菜单页面（挂载宿主内容管理目录）及各自的查询、新增、修改、删除按钮权限点；`API`权限标签 MUST 与菜单权限点一致。插件被禁用后，相关菜单与页面 MUST 由宿主完全隐藏。

#### Scenario: 菜单同步与权限校验

- **WHEN** 插件被安装启用
- **THEN** 宿主按清单同步两个菜单页面和八个按钮权限点
- **AND** 未具备对应权限点的请求被统一权限中间件拒绝

#### Scenario: 插件禁用后入口隐藏

- **WHEN** 插件被停用
- **THEN** 工作台不再展示直播间管理与直播内容菜单入口
- **AND** 历史数据保留，重新启用后恢复可用
