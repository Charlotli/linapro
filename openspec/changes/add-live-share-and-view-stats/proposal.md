# 直播分享与在线观看统计

## Why

`add-live-h5-player`变更交付了单房间 H5 观播页后，仍存在两处能力空缺：

1. **分享链路断裂**：观众只能口头转述链接；管理端无法快速产出观众可扫的进入入口，H5 页内也没有原生分享能力，直播间触达依赖手工复制粘贴。
2. **观看数据盲区**：管理端只知道"直播是否进行中"，不知道有多少人正在观看、每场直播累计被观看多少次，无法支撑教会场景对参与度的基本了解。

本变更作为`add-live-h5-player`的后续迭代，补齐"分享触达"与"观看统计"两块能力。

## What Changes

- **分享与二维码**（纯前端，无后端变更）：
  - H5 观播页信息面板新增分享操作条：支持`navigator.share`的原生环境展示"分享"按钮，其余环境展示"复制链接"按钮，复制成功给予轻提示。
  - 管理端直播间列表操作列新增"二维码"动作：弹窗展示该直播间 H5 观播链接的二维码（前端生成），支持复制链接，方便打印张贴或投屏展示。
- **在线观看统计**（后端新模块 + 前端联动）：
  - 插件数据库新增观看会话表`plugin_linapro_live_manage_view_session`：以匿名会话键（观众浏览器生成）为唯一键进行心跳`upsert`，表结构即统计口径（在线人数=最近 60 秒有心跳的会话数，累计观看=该直播的去重会话数）。
  - 插件后端新增公开统计接口（挂既有公开路由分组，免登录、免权限点）：
    - `POST /x/linapro-live-manage/api/v1/view/heartbeat`：上报观看心跳（`roomCode`+`tenantId`+`sessionKey`），返回该直播的`onlineCount`与`totalViews`；匿名请求通过显式`tenantId`解析租户上下文，语义与既有`play`接口一致。
  - H5 观播页接入心跳：观看可播内容（进行中/回放）时每 30 秒随既有轮询节律上报，展示"N 人在看"（仅进行中展示实时人数）；未开始、无直播等状态不产生心跳，心跳失败静默降级不影响观播主流程。
  - 管理端直播内容列表新增"在线人数""累计观看"两列，后端在列表装配中以单条聚合 SQL（`IN`+`GROUP BY`）批量补充，禁止逐行查询。
- 插件`apidoc`翻译资源同步新增统计接口的`zh-CN`翻译；管理端新增列文案按插件既有前端文案机制维护。

## Capabilities

### New Capabilities

- `live-manage` 能力扩展：直播分享触达（H5 分享操作条 + 管理端直播间二维码）与在线观看统计（匿名心跳会话 + 公开统计接口 + 管理端统计列）。

### Modified Capabilities

- 无修改既有能力；管理端既有接口、菜单、权限点不变，H5 观播页为叠加增强。

## Impact

- **数据库**：插件`manifest/sql/`新增一个迭代 SQL 文件（建表 + 索引），需`make db.init`与`make dao`重新生成；卸载 SQL 同步新增对应`DROP`。
- **后端**：插件新增`view`服务组件（心跳 upsert + 批量统计聚合）与公开路由绑定；既有`play`接口不动。
- **前端 H5**：`frontend/h5/`静态页新增分享操作条与"N 人在看"展示，随`go:embed`重新嵌入。
- **前端管理端**：直播间列表操作列与弹窗、直播内容列表两列，均在插件`frontend/pages/`内部闭环。
- **测试**：新增公开心跳接口契约测试断言、列表批量聚合的单元/静态验证、H5 分享条与统计展示、管理端二维码弹窗与统计列的 E2E 用例。
- **i18n**：插件`i18n.enabled: true`，新增接口的`apidoc`翻译必须同步；H5 静态页为中文独立页不受宿主语言包影响，需在任务记录中明确。
- **数据权限**：公开统计接口为匿名写入的合理例外（权威边界为房间编码 + 显式租户参数，不泄露范围外数据），管理端统计列跟随既有直播列表的权限边界，例外说明写入`design.md`。
