# 直播公告与圣经阅读器

## Why

观众在 H5 观播页只能被动接收当天的聚会节目信息：聚会通知（临时调整、特别聚会、奉献说明等）没有触达渠道，聚会中读经环节观众也无法在页面上跟随经文。本变更补齐两个能力：管理端按直播间配置公告，观众在 H5 通过独立入口点开查看公告列表；H5 内置圣经阅读器，可按 66 卷书卷与章节逐节阅读和合本经文（数据来自既有 MySQL 库 `bibleid`/`bible` 表导出），为后续聚会读经联动打基础。

## What Changes

- **数据库**（插件迭代 SQL，幂等）：
  - 新增公告表 `plugin_linapro_live_manage_announcement`：租户级，关联直播间，字段含标题、内容、启用开关、排序、审计字段；含 `(tenant_id, room_id)` 查询索引。
  - 新增圣经书卷表 `plugin_linapro_live_manage_bible_book` 与经文表 `plugin_linapro_live_manage_bible_verse`，结构对齐导出源（书卷 sn 主键、新旧约分类、章节总数、简称/全称；经文唯一键卷/章/节、经文内容、音频起止毫秒备用字段），经文表对书卷表外键约束。
  - Seed DML：66 卷书卷全量 + 31103 节经文全量，由用户提供的 MySQL dump 转换为 PG 幂等语句（`ON CONFLICT DO NOTHING`，唯一键为真实业务键）。
- **后端**：
  - 管理端公告 CRUD（挂既有直播间权限点 `live:room:*`，按直播间维度管理）：`GET/POST/PUT/DELETE /api/v1/announcement`。
  - 观众端免登录接口：`GET /api/v1/announcements?roomCode=&tenantId=` 返回该直播间启用中的公告列表（启用状态、按排序与创建时间排序，全量不分页——公告数量天然有界，上限保护）；`GET /api/v1/bible/books` 返回 66 卷书卷；`GET /api/v1/bible/chapter?volumeSn=&chapter=&tenantId=` 返回单章逐节经文。匿名端点租户语义与 `play` 一致。
  - 圣经数据为全局静态内容：按书卷查询不做租户过滤（经文内容无租户属性），仅管理端写路径走租户与权限链。
- **管理端前端**：直播间管理列表新增"公告"操作入口，打开公告管理弹窗（既有 useVbenModal 模式）：列表 + 新增/编辑/删除/启用开关，字段为标题、内容、启用状态、排序；API client 补齐对应方法。
- **H5 观播页**：
  - 信息面板新增两个独立入口按钮"公告""圣经"（与分享条同级）：公告打开公告面板（列表卡片展示标题与内容），圣经打开圣经阅读器（书卷选择 → 章节选择 → 逐节经文，上一章/下一章导航）；均以底部滑出面板承载，不遮挡播放器主流程，关闭即回到观看。
  - 公告数据在页面加载时静默拉取一次；圣经书卷数据懒加载（首次点开时请求），单章经文按需请求。
- 插件 `apidoc` 翻译资源同步新增接口的 `zh-CN` 翻译（插件 `i18n.enabled: true`）。

## Capabilities

### New Capabilities

- `live-manage` 能力扩展：直播间公告（管理端 CRUD + 观众端免登录列表 + H5 公告面板）与圣经阅读器（书卷/经文静态数据 + 免登录阅读接口 + H5 阅读器）。

## Impact

- **数据库**：插件迭代 SQL 新增三表 + 经文 Seed DML（幂等）+ 卸载 SQL 同步；`make dao` 重新生成三表 DAO。
- **后端**：插件内部新增 announcement/bible 两组 api/service/controller，路由绑定进既有 viewer 与 admin 分组；不触碰 lina-core。
- **前端**：管理端直播间页面新增公告弹窗（复用既有 modal 模式）；H5 新增两个面板组件（纯静态资源，无构建依赖）。
- **i18n**：新增接口 apidoc `zh-CN` 翻译 + 管理端新文案双语键；H5 为中文独立页无语言包依赖。
- **性能**：公告列表有上限保护；单章经文最大 176 节（诗篇 119 篇），集合化单查询；书卷列表为 66 行静态数据；无 N+1 风险。
